# Тестовый корпус AH-MemoryHub

Машиночитаемый длинный корпус находится в
`docs/testing/heterogeneous-corpus.json`: десять документов из десяти доменов,
каждый по десять предложений, с обязательными утверждениями и контрольными
вопросами. Он не включает отложенные отрицания и исключающие конструкции.

\`gold-v1.json\` и \`gold-v2.json\` сохранены как ранние targeted benchmarks.
Основной \`gold-v3.json\` охватывает все десять документов: 100 исходных
предложений, 106 размеченных фактов и 237 ролевых назначений. В каждом домене
одинаково размечены семь предложений; остальные служат неразмеченным контекстом.

Воспроизводимый offline smoke:

\`\`\`powershell
cd backend
.\.venv\Scripts\python.exe scripts\evaluate_corpus.py --provider rule
\`\`\`

Реальный M1 через OpenRouter запускается только явно:

\`\`\`powershell
.\.venv\Scripts\python.exe scripts\evaluate_corpus.py --provider nitro --execute --out ..\docs\testing\results\m1-m2-m3-nitro-v3.json
\`\`\`

Зафиксированный Nitro-результат \`perception-ir-v3.23\`: M1 micro-F1 \`0,771\`,
weighted-F1 по всем размеченным ролям \`0,784\`, weighted-F1 по обязательным
SUBJECT / OBJECT / LOCATION \`0,772\`; совпало 192 из 237 gold-назначений.
Macro-F1 по десяти документам \`0,770\`, диапазон по доменам \`0,622–0,939\`.
M2 содержит 100 вопросов — пять независимых фолдов официального размера 20 —
с эталонными ответами и полными путями FOLLOW / IS-A / CAUSE глубины 1–6:
пройдено 100/100 трасс, trace pass rate \`1,000\`, ExplainScore каждого фолда и
средний ExplainScore \`0,533\`. M3 содержит восемь сценариев двух топологий:
удалено 3700/3700 потерянных узлов за 50 тактов, сохранено 750/750 связанных
узлов, GC efficiency \`1,000\`, ложных удалений \`0\`. Это внутренний versioned
benchmark, не внешний leaderboard оргкомитета.

План нагрузочного прогона без сетевых запросов:

```powershell
cd backend
.\.venv\Scripts\python.exe scripts\load_corpus.py --repeat 10
```

Реальный прогон 100 уникальных документов через Nitro выполняется только с
явным флагом и расходует кредиты провайдера:

```powershell
.\.venv\Scripts\python.exe scripts\load_corpus.py --repeat 10 --concurrency 2 --execute
```

Каждый блок ниже вставляется в Ingestion отдельно. Для повторяемой проверки:

1. Выберите модель парсера и нажмите «Собрать кандидатов».
2. Проверьте роли, исходные фрагменты и логические операторы кандидатов.
3. Примите кандидатов вручную либо включите автоприём.
4. Задавайте вопросы только после записи фактов в память.

## 1. Базовая причинная цепочка

```text
Перегрев насоса вызвал остановку агрегата в насосном зале. Остановка агрегата привела к снижению давления. После этого оператор применил ручной ключ.
```

Проверяет CAUSE, локацию внутри события и отсутствие ложного FOLLOW по одному маркеру «после этого».

## 2. Двигатель: OR и составное свойство

```text
Двигатель установлен в цехе А или в цехе Б. Он принадлежит компании «Промтех». Датчик двигателя красный и горячий. Перегрев двигателя вызвал аварийную остановку.
```

Проверяет OR, анафору «он», принадлежность, два атомарных состояния одного объекта и CAUSE.

## 3. Заяц — эталон раздела 7 монографии

```text
Заяц — маленький дикий зверёк, который обитает на лугу или в лесу. У него сильные задние лапы, поэтому бегает он очень быстро. Уши зайца длинные, а хвост — круглый и пушистый. Летом шерсть зайца коричневого цвета, а зимой — белого.
```

Проверяет IS-A, OR, причинность, свойства частей и состояния с временными условиями.

## 4. Компрессор К-17

```text
Компрессор К-17 установлен в цехе А или в резервном машинном зале. Компрессор принадлежит компании «Промтех» и используется для подачи воздуха в производственную линию. У компрессора есть датчик температуры ДТ-4. Датчик ДТ-4 имеет красный корпус и находится в горячем состоянии. Перегрев датчика вызвал аварийный сигнал на пульте оператора. После аварийного сигнала произошла автоматическая остановка компрессора. Остановка компрессора привела к снижению давления в производственной линии. Затем оператор Иванов применил ручной ключ для открытия резервного клапана. Открытие резервного клапана восстановило подачу воздуха и повысило давление. После восстановления давления аварийный сигнал отключился, а компрессор остался остановлен до завершения проверки.
```

## Точечные регрессионные фрагменты

```text
Этикетка E-9 имеет синий фон и находится в повреждённом состоянии.
```

Ожидаются два разных атомарных состояния одного субъекта.

```text
Сборка имеет номер 841 и находится в статусе «кандидат».
```

Ожидаются номер и статус без потери одного из свойств.

```text
Наблюдение оставалось приостановленным до следующего окна связи.
```

Ожидается состояние вместе с временной границей.

```text
После аварийного сигнала произошла автоматическая остановка компрессора.
```

Ожидается FOLLOW: остановка следует после аварийного сигнала.

```text
После этого инженер выполнил откат.
```

Без предыдущего явно названного события FOLLOW создаваться не должен.
