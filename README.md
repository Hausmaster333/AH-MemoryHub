# AH-MemoryHub

Гибридный нейросимволический ИИ-агент с ассоциативно-гетерархической (АГ) памятью для цифрового двойника оператора АСУ ТП.

Проект подготовлен в рамках хакатона «Воспламенение 1.0»

## Идея проекта

Вместо классического RAG на векторных эмбеддингах агент хранит знания в виде структурированного графа фактов с ролями участников (акторов). Гипотеза: такая структурная память даёт более объяснимые и проверяемые ответы, чем поиск по embedding-схожести — каждый ответ можно проследить до конкретных фактов, которые на него повлияли.

Сквозной пример, использующийся для иллюстрации работы системы: инцидент перегрева насоса по показаниям датчика ДТ-4.

### Основные компоненты

- **LLM-парсер** — извлечение фактов из документов с ролями и уровнем уверенности
- **АГ-память** ⟨S, C, P, H, L⟩ — ядро хранения знаний (см. ниже)
- **Ignition Engine** — механизм распространения активации по графу
- **Модуль генерации ответов** (`answering.py`)
- **DSL-интерпретатор** — язык запросов к памяти
- **Garbage Collector** — очистка неактуальных/невостребованных узлов
- **Web-интерфейс**

### Модель памяти АГ = ⟨S, C, P, H, L⟩

Факты проходят уровни:

`S` (символы, устойчивый UID) → `T` (шаблон, напр. `CAUSE: SUBJECT→OBJECT`) → `N` (ассерт-гипернода, напр. «перегрев ДТ-4 → сигнал тревоги», с UID/весом/источником) → секция памяти.

Секции памяти:
- **C** — общие знания
- **P** — устойчивая модель агентов/объектов
- **H** — конкретные эпизоды
- **L** — ассоциативные связи (`CAUSE`, `FOLLOW`, `IS-A` и др.)

Формальная модель основана на монографии Р. В. Душкина.

### Ignition Engine

1. Seed-узлы (точка входа)
2. Импульсы вдоль связей/гиперсвязей
3. Возбудимость (функция затухания)
4. Перенос элементов выше порога в рабочую память
5. Правило Хебба — обновление весов при совместной активации

Важно: Ignition Engine отвечает только за распространение активации, **не за генерацию ответа**. Результат его работы — путь UID’ов фактов, реально повлиявших на ответ, что делает вывод полностью верифицируемым.

## Метрики

| Метрика | Значение | Статус |
|---|---|---|
| M1 — точность извлечения ролей акторов | F1 = 0.772 (237 ролей, 10 сценариев) | Измерено (внутренний прогон) |
| M2 — глубина объяснимого вывода | 100/100 полных путей, ExplainScore = 0.533, глубина 1–6 | Измерено (внутренний прогон) |
| M3 — эффективность сборщика мусора | 1.000 (3700/3700 удалено, 0 ложных срабатываний) | Измерено (внутренний прогон) |
| M4/M5 — сравнение с RAG / экономический эффект | AH 22/40 vs RAG 34/40 на корпусе 30 док. / 40 вопросов (Qwen 2.5 7B) | Предварительно, неофициально — не является измеренной метрикой |

M1–M3 — внутренние измерения проекта. M4/M5 — предварительные неофициальные данные, требующие отдельной оговорки и не подлежащие смешению с итоговым сравнением до финального прогона.
